# MochiCode hybrid routing contract

This portable contract defines how project work enters MochiCode Auto. It keeps small work fast while
reserving deterministic state and evidence handling for work that can actually benefit from it.

## Automatic routes

| Route | Select it when | Execution boundary |
| --- | --- | --- |
| Direct current parent | Trivial or one-step. | No child. |
| Direct selected authority | Substantive visual, product, architecture, tightly coupled, ambiguous, or debugging work. | Preserve the running parent and effort; Sol High is the installed default. |
| Direct Astra High candidate | Current session identity shows the running selected parent is `gpt-6-astra`; catalog omission does not disprove it. | Astra owns the same quality loop directly, preserving its selected effort. No automatic Manager layer. Sol remains the installed fallback until matched promotion. |
| Bounded Luna Medium worker | Sizable independent implementation leaf with a concrete expected saving from leaf size, slow verification, external build latency, isolation, or batch volume. Independence alone is insufficient. | A real Luna Medium child implements; parent verifies; Max is escalation. |
| Authority-led fan-out | Frozen interfaces, at least two disjoint independent leaves, and a concrete expected critical-path saving. | Start with two, cap normal waves at three, integrate under the current selected authority. |
| Manager Mode beta | Explicit Manager Mode implementation request. Automatic classification is shadow-only until matched promotion. | The current authority parent manages one direct non-spawning Sol High implementer across phases; parent verification, deterministic rotation, parking, stop/resume, and one replan are required. |
| Experimental controller | Explicit experiment only after promotion criteria are met. | Never selected automatically. |

MochiCode Auto is the only top-level workflow. The user supplies only the real goal; routing and conditional mechanisms preserve the selected parent and effort. Manager Mode requires an explicit Manager Mode implementation request.

## Core roles

- Sol High is the default substantive parent and owns decisions, implementation when appropriate, integration, debugging, live verification, and final judgment. Max is consequential-only.
- A running selected Astra parent takes the same direct authority role, preserving its effort. New profile installation requires catalog support; use only efforts advertised by the active host. Existing Luna and Terra support roles remain bounded; automatic default promotion requires two matched tasks.
- Small or sequential routine work remains with the current selected authority. Luna Medium is a real child only for sizable independent leaves with hard checks; Max is escalation after failed acceptance.
- Terra is absent from default native routing and optional only in explicit controller experiments.
- Manager Mode separates direction from execution. The authority manager does not edit production code while exactly one direct Sol High child owns the active phase. That child is configured to disable spawning; verify the active host honors the controls before claiming enforcement. Child failure before a write falls back to the direct authority parent.
- A warranted quality gate uses one fresh evidence-bound read-only Sol High verifier, one parent adjudication, one repair at most, then reruns all checks and stops. Three judges are exceptional.
- The deterministic controller owns persistent workflow state and every retry, evidence, and merge
  decision only on an explicitly selected experimental route.

The complete archive-role mapping is machine-readable in `config/role-dispositions.json`. The five
active core agent definitions are in `config/agents/`.

## Invariants

- Keep the existing plan and contract packet schemas unchanged.
- Exactly one writer owns each file, module, configuration area, migration, or shared state.
- Maximum policy depth is one, current selected authority to child. Children must not spawn descendants. Ordinary native restrictions are behavioral instructions unless host tool denial is verified.
- Eight active child threads is a host ceiling. Automatic waves start with two and cap at three.
- Total waves are bounded by the goal, declared budgets, stop conditions, and host limits.
- Manager Mode keeps 3 to 12 explicit phases, one active phase, two attempts per phase, one replan, a wave-one vertical slice, and independent child plus parent receipts. Automatic candidates require 3 to 6 phases, at least 6 production files across 2 components, complete phase/final oracles, frozen decisions, one sequential writer, confirmed child controls, rejected fan-out, and no heavier-controller need.
- Repository files do not widen host permissions, replace user approvals, change the host context
  limit, or add recursive agent configuration.
