# Skill system coexistence

`config/skill-dispositions.json` is the portable disposition registry for Ana's user-owned skills.

MochiCode Auto is the sole automatic top-level workflow for substantive project work. Other skills may constrain a selected route as a guardrail, perform one bounded specialist job, or run only when explicitly invoked. They may not establish a competing project loop.

Retire obsolete skills only after the exact candidate version is installed and a fresh-task routing canary passes with a raw receipt bound to that manifest. Until then, keep candidates available with narrow explicit-only descriptions. When retiring, move their complete folders outside active skill-discovery roots, keep a timestamped backup and restorable archive, and never edit OpenAI-managed system, plugin-cache, or curated skill files.

Legacy DOCX, PDF, PPTX, and XLSX skills remain explicit fallbacks until the corresponding managed runtime passes one representative read canary and one representative write-and-render canary. Only then may the legacy folder move to the recoverable archive.

Task-specific specialist workflows may use bounded children only when the parent is the active top-level route. Children never spawn descendants, one writer owns each output, and the parent records model, effort, owned paths, result, tests, and stop reason.
