# Workflow details

## Route selection

1. Preserve the user's real goal and define observable completion automatically.
2. Handle trivial work directly without a child.
3. Use direct Sol High for substantive visual, product, architectural, tightly coupled, ambiguous, or debugging work.
4. Use a real Luna Medium child only for a sizable independent implementation leaf with a concrete expected saving from leaf size, slow verification, external build latency, context isolation, or batch volume. Independence alone is insufficient. Keep tiny or sequential work direct Sol.
5. Fan out only frozen, disjoint leaves under a Sol parent, starting with two and capping normal waves at three.
6. Keep the deterministic controller manual and experimental until its published promotion gates pass.

## Native route

1. Sol High is the substantive parent and may implement directly. Sol owns decisions, integration, live verification, correction, and final judgment.
2. Sol Max is reserved for consequential whole-product, architecture, security/release, or repeated quality-failure decisions. Ultra is exceptional.
3. A proven Luna Medium child implements sizable independent packets with hard checks. Luna Max is escalation-only. Parent-executed work must never be reported as Luna.
4. Fan-out remains Sol-led. Freeze interfaces first, assign disjoint paths, and continue in waves only when the first wave earns its overhead.
5. Terra is absent from the default native route and remains optional only inside an explicitly selected controller experiment.
6. When a judge gate is warranted, three fresh orthogonal read-only judges run once. For mixed UI-and-logic work, default to product hierarchy, accessibility and interaction, and state integration. Sol adjudicates once, permits one integrated repair, reruns the same checks, preserves a human comparison for taste, and stops.

## Task and child labels

For every newly created parent task, use `[ROLE | MODEL | EFFORT] concise objective` as the visible title. For generated child labels that cannot be overridden, put `ROLE`, `MODEL`, and `EFFORT` at the start of the packet and the returned handoff. This is observability, not a permission to alter model selection or rename existing user tasks.

## Experimental deterministic route

Do not select this route automatically. Its current implementation remains unpromoted until it persists the Sol decision, validates packet affordability, performs one real replan, makes final review conditional and compact, and aggregates usage by role and model.

1. Sol produces the binding product/architecture decision and a bounded dependency graph. Wave one contains a runnable vertical slice. Whole-product and redesign decisions use Sol Max.
2. Terra mechanically converts the accepted Sol decision into a cold-start contract, executable checks, protected paths, allowed write paths, and evidence requirements without adding product or design choices.
3. The controller runs the baseline in a read-only, network-disabled OS sandbox, proves a valid failing state, and refuses any workspace or protected-input mutation.
4. The controller durably reserves one bounded attempt. Luna Max receives only the packet contract, the bound Sol decision when applicable, and relevant project context in a fresh isolated worktree. The standard service tier remains the default.
5. The controller reruns protected verifier files, checks workspace and protected hashes, records the diff-plus-verifier fingerprint, and writes hash-bound receipts.
6. The controller commits the verified packet. Terra receives that immutable commit identity, goal, contract, diff, hashes, and raw evidence. It never receives Luna reasoning or trajectory.
7. Every packet requires hard verification and a GREEN Terra review. Neither model verdict can override a failed deterministic gate.
8. The controller rechecks packet identity immediately before merging only into its integration branch. Failure rotates the packet behind independent peers. A second consumed attempt or repeated fingerprint parks it.
9. When ready work is exhausted, Sol may replan once from verified state. Then the run finishes, blocks honestly, or stops on budget or safety.
10. The controller reruns every accepted contract against the final integration identity. Sol reviews that exact identity. A human decides whether to merge.

## Shared limits

- Preserve the packet and contract schemas already in `schemas/`. Do not add routing metadata to those payloads.
- Exactly one writer owns each file, module, configuration area, migration, or shared state.
- Maximum orchestration depth is one, primary Sol parent to child. Children never spawn descendants.
- Eight active child threads is a host ceiling. Start with two and use no more than three live workers per wave until larger waves are benchmark-promoted.
- Child results normally stay below about 1,200 tokens and use `STATUS`, `FACTS`, `CHANGES`, `TESTS`, `RISKS`, and `NEXT`.

Parallelize only disjoint write sets and independently verifiable questions after predicting a concrete critical-path saving. Never parallelize two workers that may edit the same files, and never treat independence by itself as sufficient reason to delegate.

## Progress and human-gate discipline

- A future human test does not block the project. Prepare the coherent testable slice, the human question, feedback capture, and acceptance criteria, then continue independent reversible work.
- Internal failure is work, not a blocker. Missing controller state, failed or silent children, model refusal, tool failure, timeout, red tests, unresolved architecture, worktree confusion, and integration conflicts require a changed method.
- Recovery order is: inspect current files and receipts; change method after two matching failures; narrow the packet; use a fresh or stronger justified child; switch safe execution route; diagnose directly; repair prerequisites; park only the failed packet; continue independent work.
- A task may report blocked only after it identifies the exact missing human authority, unavailable external credential/service/hardware, spending/production/destructive permission, or other external state and confirms that no useful reversible packet remains.
- After two failed attempts, change method. Park a repeated failure fingerprint and continue independent work instead of replaying the same loop.
- Send progress only at meaningful milestones. Do not emit repeated waiting updates or complete a turn with no change, check, packet advance, or precisely evidenced gate.
- Parent handoffs record each child’s role, model and effort, owned paths, tests, result, and stop reason; child prose remains concise.
